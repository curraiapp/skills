## Common contract

Import the helper generated by `scripts/instrument.mjs`. Create a session once
at the conversation boundary and reuse that UUID for every turn. Create a parent
`agent` event for an agent turn and use its event ID as `parentId` for nested
model, tool, retrieval, guardrail, and evaluator events.

The helper sends:

- `POST /api/v1/capture-session` before events;
- `POST /api/v1/capture-event` for every captured primitive;
- `x-currai-workspace-id` and JSON content headers;
- redacted JSON strings in `args` and `result`;
- a two-second timeout that is isolated from the product request.

Use a stable authenticated user ID. For anonymous traffic, persist a random
anonymous ID in the application's existing session mechanism; do not derive it
from prompts, IP addresses, or authorization tokens.

## Next.js and Vercel AI SDK

Instrument the server route or server action containing `generateText`,
`streamText`, or `generateObject`. Never import the helper into a Client
Component.

1. Resolve or create the conversation UUID before the model call.
2. Await `captureCurraiSession(...)` before the first event in a new conversation.
3. Create a model event UUID and record `Date.now()` immediately before the AI
   SDK call.
4. For non-streaming calls, capture the resolved text or object after success.
5. For streaming calls, capture the final accumulated text in the completion
   callback. Do not consume or replace the response stream.
6. Capture thrown provider errors with `success: false`, then preserve the
   application's existing error path.

Include the provider model name and usage returned by the AI SDK in metadata.
If the route invokes tools, create child `tool` events around each real execute
handler rather than inferring tool results from model text.

## OpenAI and Anthropic TypeScript

Wrap the actual `responses.create`, `chat.completions.create`, or
`messages.create` call. Keep the original request object and response type.
Capture a redacted request summary as `args`, the provider output as `result`,
and provider usage/model identifiers as metadata.

For streaming APIs, use the provider's final-message or completion hook. Do not
iterate the stream a second time. For OpenAI tool calls or Anthropic tool-use
blocks, capture the application's real tool execution separately as a child of
the model or agent event.

## LangChain and Mastra TypeScript

Instrument the application-level `invoke`, `stream`, agent execution, or
workflow call rather than patching library internals. Use an `agent` event for
the outer run. Capture application-owned tool functions as child events and
model calls when the framework exposes safe callbacks.

Do not add a Currai package, duplicate an existing OpenTelemetry pipeline, or
replace framework callbacks. Currai's native helper is sufficient for the
application boundaries needed by User Stories, Intents, Violations, and Errors.

## TypeScript MCP servers

Instrument the server-owned tool handler registered through `server.tool`,
`registerTool`, or `setRequestHandler`. Create or recover a stable session UUID
from the authenticated application session. Never use or transmit a raw bearer
token as the user ID.

Capture each invocation as `kind: "mcp_tool"`, with the tool name in `name`,
redacted arguments, the returned content, latency, and failure status. Do not
modify the MCP transport or response envelope.

## Python model and agent applications

Import `currai.py` from the generated helper location. The helper is synchronous
and dependency-free. In async FastAPI, Starlette, Django async, or agent code,
call it with `await asyncio.to_thread(...)` so the short HTTP request does not
block the event loop.

Wrap the real OpenAI, Anthropic, LangChain, or application agent call in
`try`/`except`. Capture success after the provider result and capture the error
before re-raising it. Preserve provider response objects and streaming
semantics. Include usage and model metadata when the provider exposes them.

## Python MCP servers

Wrap the registered FastMCP or MCP tool function without changing its decorator,
signature, return value, or exception behavior. Capture the actual arguments and
result as `kind="mcp_tool"`. Derive user and session identity only from stable,
validated application context and never forward credentials.

## Guardrails and evaluators

Capture the actual guardrail or evaluator execution even when it blocks a model
call. Use `success` for execution success, not policy outcome. Put structured
outcomes such as `allowed`, `score`, `label`, `threshold`, and `reason` in the
result or metadata.

Use `metadata.intent` or `metadata.violation` only when the application already
produces that exact classification. Currai otherwise matches captured evidence
against the intents and rules configured in the dashboard.
